# H5 预览兼容规则

PoemUI 的真实产物是微信小程序原生组件，H5 预览站只用于快速查看视觉、主题、状态和组件目录。不要把 H5 预览代码当成小程序源码复制。

## 不直接复用 WXML 的原因

小程序和浏览器存在语法差异：

| 类型 | 微信小程序 | H5 预览 |
| --- | --- | --- |
| 结构 | `.wxml`、`slot`、`wx:if`、`bindtap` | `.html`、`template`、`data-*`、`click` |
| 样式单位 | `rpx` 可用 | 浏览器不支持 `rpx` |
| 组件注册 | `usingComponents` | 原生 HTML/CSS/JS |
| 样式隔离 | `styleIsolation` | 普通 CSS 作用域 |
| 事件 | `triggerEvent` | `CustomEvent` 或普通事件 |

## 当前策略

1. 组件真实样式继续写在各组件 `.wxss` 中。
2. H5 预览站使用 `preview/styles.css` 维护一份浏览器可渲染的镜像样式。
3. H5 尺寸使用 `px`，按小程序常见比例近似换算：`1px` 约等于 `2rpx`。
4. H5 类名尽量沿用 `pui-*`，方便对照，但不作为组件源码。
5. 组件示例必须同时展示 WXML 引入路径和 H5 兼容说明。
6. 毛玻璃的 `backdrop-filter` 在 H5 里更稳定，小程序端必须同时保留清晰背景、边界和阴影 fallback。
7. Icon 预览使用 `npm run icons:generate` 生成的 `preview/icons-data.js` 与 `preview/icon-font.css`，避免 `file://` 预览时浏览器阻止 fetch 本地 JSON。资源搜索使用共享 PUI Input、分类与资源卡使用共享 PUI Button，资源卡图形复用同源 `iconComponent`。H5 与小程序都从稳定码点渲染同一 WOFF2 字形，并以 `currentColor` 接收实体色与 PUI Token；`premium` 是公开语义名，固定映射既有 Lucide `crown`，并由生成链在两端共享的 WOFF2 轮廓中上移 `1.5/24` 画布单位以对齐标题视觉基线，通用 `crown` 不受影响，任何一端都不能用页面 CSS、私有 SVG 或字符替代。`icons-data.js` 不得携带 SVG body/path，H5 不得以 mask/inline SVG 掩盖字体加载失败。点击资源卡会先回写 `name`，再通过同源真实剪贴板路径复制该图标名，并根据实际结果复用 Toast 的 success/error 短暂提示；这不是 `pui-icon` 的 click API。
8. Accordion / Collapse 预览必须保留内容容器并以测量的 `scrollHeight` 过渡像素 `max-height`、透明度与轻位移；小程序端对应保留 `.pui-collapse__content-inner` 并以 selector query 测量高度，不能使用 `height:auto`、`max-height:none`、`display:none` 或条件移除内容节点伪造收起。Collapse Trigger 是组件自有 `view[role=button]`，H5 必须镜像为组件根并补 Enter/Space 与 `source=keyboard`，不得机械替换成 raw button 或 PUI Button；Icon 仍调用共享镜像。H5 与原生端都必须严格区分数字 `0`、布尔 `false`、空字符串和字符串 `"0"`，共享 `error > loading > content > empty`、数组 value 受控、default/card、collapse-panel Generic、change/retry 和固定 500ms/1ms 合同；不得恢复 input/open/close、业务实例方法或私有 duration/easing。
9. SwipeCell 的 H5 镜像只实现真实滑动原语：H5 使用 Pointer Events，原生端使用 touchstart/touchmove/touchend/touchcancel；两端超过 10px 后区分横纵方向，横向超过操作区 30% 才展开。数组动作必须调用共享 PUI Button，前景内容必须调用消费者组合的 Cell；default/left/right Slot 不由组件伪造业务交互。H5 以同源 `click({ action, source })`、`dragstart`、`dragend` 映射公开事件，轻点内容或数组操作后收起；只过渡 transform，拖动帧无 transition，固定 500ms/低动效 1ms，且不提供 loading、速度阈值、受控写回或实例方法假能力。
10. Dialog 预览必须以 `opacity + transform` 完成固定 `500ms` 出现与退场，`reduceMotion` 或系统低动效压缩为 `1ms`；17 个 Props、受控 `visible`、按钮与 actions、八个具名 slot、遮罩、层级、滚动保护和低动效必须即时映射到 H5 与 WXML。Dialog 的 H5 状态机必须由 `bindPreviewRuntime()` 注册 `bindDialogPreviewRuntime()`，确保入场计时器、焦点、Escape 和真实遮罩/按钮事件都能生效；不得只保留初始透明节点。展示分区必须位于透明 `pui-dialog-showcase__content`，消费 `14px` 预览面板内距和 `18px` 分区间距；遮罩舞台仍以 `inset:0` 覆盖完整 PreviewDevice，Panel 在层内使用同一安全内距。Header 必须镜像可选 header-left/标题列/默认 Close 三列等宽边轨，左右按钮留在正常文档流。Dialog 复用 Popup 唯一 Surface 时清除 Popup Content 的重复 padding，Header/Content/Footer 直接使用自身 inset；Footer 按一个或两个真实动作形成一列或两列全宽 Grid。Dialog 自然增高到 PreviewDevice 可用上限，Header/Footer 固定，超长 Content 内滚。Cancel/Close/可关闭遮罩请求父级回写，Confirm/Action 不自动关闭；Loading、Empty、错误和重试必须由 content Slot 的真实 PUI 组合承担。H5 可增加 Escape 与焦点提示，但不得把 DOM focus trap 或硬件键盘能力写成小程序合同。
11. Alert 预览必须使用与原生一致的受控/非受控显隐语义：默认 `visible=null + defaultVisible=true`，受控关闭或重新打开由预览父级真实写回；点击关闭后保留 `opacity + transform` 退场帧再移除镜像。概览只保留提示和必要恢复入口，事件、Props 和 Slot 术语进入 API/属性。主题、soft/tinted、图标、verticalAlign、兼容 center、slot、时长、缓动和低动效都必须同步到 H5 与 WXML；tinted 的前景/辅助前景必须使用同一 theme Token，Icon 到正文固定使用 normal 内容组合间距，不能退回紧凑 small 间距。
12. Aspect Ratio 的 H5 镜像也必须以 `padding-top = 高 / 宽` 保留空间，不能把浏览器 `aspect-ratio` 当成原生端前提；比例切换只过渡 `padding-top`，时长、缓动、低动效、圆角类名、边界和 overflow 与 `pui-aspect-ratio` 的 WXML/WXSS 同步。默认概览只展示用户可理解的媒体内容，不得泄漏 `Default slot`、`clipped content` 等工程诊断。
13. Button Group 的 H5 镜像必须以同一个 `role=group` 根包裹真实的内部 Button 镜像；默认全宽，集合根独占阴影，连续子 Button 不设 gap、外圆角或独立阴影。ButtonGroup 本身只负责布局和组级禁用，不能把子 Button 的点击伪造成组级 `change`。原生端用透明遮罩阻断 disabled 时的 slot 触摸，H5 则让每个 Button 进入原生 `disabled` 属性。
14. Card 的 H5 镜像必须与 WXML 的 header/content/footer 条件一致；不得添加 Card API 中不存在的“展开”按钮或状态。`clickable` 只呈现 Card 自身的 `click`，footer 内部 Button 必须保留独立 click，不能被父级 click 伪造或吞掉。
15. Divider 的 H5 镜像必须保持横竖布局、`content` 与 `showContent` default slot 的真实条件；默认无内容横线必须连续，间距只属于真实 content 节点。分隔符是纯展示组件，不得为了预览加入 click/input、受控状态、方法或动画。概览按基础用法/文字与对齐/布局与线型分区，后续标题使用 18px section gap；API 必须完整展示 7 Props、1 Slot、0 Events。长 content 需要和 WXSS 一样可收缩、截断，避免窄屏溢出；`role/aria-orientation/aria-hidden/aria-label` 与 WXML 同步。
16. Badge 的 H5 镜像必须与原生共享 12 Props、0 Events、默认/count 两个 Slot，以及 count 的零值、上限、空白、布尔拒绝和 `null` Slot 语义；`content` 只表示宿主文本，默认 Slot 表示复杂宿主，没有宿主时自动独立布局，附着时固定右上角并由 offset 调整。它是纯展示叶子，点击、disabled、loading、selected 等状态必须由 Button/Cell/Tabs/Tabbar 宿主承担，不得通过点击递增、显隐生命周期、事件卡或重置伪造原生不存在的能力。Tag 不得再被外层原生 button 包裹；closable 时只保留与 WXML 一致的组件自有关闭根，组合 PUI Icon，按 `28rpx / 14px` 点击区和 `24rpx / 12px` 图标镜像，双轴居中并在 H5 补齐 Enter/Space；演示层“恢复标签”必须调用 PUI Button。
17. Avatar 的 H5 镜像必须使用真实 `<img>` 的 `load/error` 映射内部 Loading、图片淡入、回退和 `hideOnLoadFailed`；非空 `src` 先进入 `aria-busy=true`，资源结束后必须关闭自动等待态，缓存资源还要检查 `complete/naturalWidth`。`loading=true` 则持续保持 Avatar 内部 PUI Loading，即使图片已在后台完成；页面不得在外部拼第二份 Spinner。`lazy=true` 映射 `<img loading="lazy">`，否则为 eager；lazy 只决定请求时机。只有 `error` 是公开事件，load 只更新内部绘制。Avatar 是展示叶子，不发布 click/clickable/disabled，组合操作必须使用外层 PUI Button/Cell；不得用点击切换“失败”或“加载完成”。默认 slot 在 H5 中以内部 Icon 组合镜像表示，固定 normal duration 与 `reduceMotion/prefers-reduced-motion` 必须同步到 WXML/WXSS。
18. Image 的 H5 镜像必须与原生共享 14 Props、`load/error`、默认覆盖 Slot 和 `error > loading > empty > 资源状态` 优先级，并以真实 `<img>` 的 `load/error` 映射 loading、loaded、error 与 empty，缓存资源以 `complete/naturalWidth` 同步；不得保留手工“切换状态”按钮或只修改提示文字。图片的 width/height 过滤规则不能宽于小程序端；loading 必须调用共享 `loadingComponent`，覆盖内容中的 Tag 与交互宿主必须调用共享 PUI 镜像。Image 常规模式代码正文必须展示组件引用、基础、状态、裁切和覆盖内容五段，全部通过同一 `makeUsageCode` 与 PUI Copy IconButton 生成/复制；基础段不绑定事件。Image 是展示叶子，不发布 click/clickable/disabled，Slot 事件属于消费者；需要打开或禁用图片时由外层 PUI Button/Cell 承担。`webp` 由浏览器格式协商近似，`showMenuByLongpress` 映射为浏览器上下文菜单策略，并记录 lazy-load、`widthFix` / `heightFix` 与微信解码的平台差异。固定 500ms 淡入、`reduceMotion` 和 `prefers-reduced-motion` 必须跨端一致。
19. Grid 的 H5 镜像必须把 `items=[]` 呈现为 empty，并遵循 error、loading、content、empty 优先级；Item 点击只显示原生 `click` 详情，不得加入原生 API 中不存在的 active/selected 状态。每个入口与 WXML 一样调用 PUI Button 默认 Slot，内部 Badge、Icon 与 footer Tag 调用共享 PUI 镜像；禁止用私有原生 button 或手写徽标替代，禁用和间距上限必须与 WXML 同步。
20. ScrollArea 对齐 TDesign ScrollView：公开固定高度、受控 `scrollTop`、`scrollIntoView`、`gradientOverlay`、`gradientOverlayColor`、`gradientOverlaySize` 与辅助名称，并发布唯一真实 `scroll` 事件。小程序端固定为原生纵向增强 `scroll-view`、隐藏滚动条并在组件内部固定开启 `scroll-with-animation=true`；H5 也使用真实可滚动容器，父级改写不同的 `scrollTop` 时调用原生 `scrollTo({ behavior:'smooth' })`，与当前原生位置相同的值视为用户手势回声、不得重启惯性；非空 `scrollIntoView` 则按原生优先级平滑定位到同 id 的 slot 节点，系统 `prefers-reduced-motion` 时立即定位。该平滑行为不扩张为 `scrollWithAnimation/duration/easing/reduceMotion` Props，也不伪造完成事件。`gradientOverlay` 默认 `true`，在唯一真实视口的顶/底维护与滚动内容同级、`pointer-events:none`、`aria-hidden` 的固定层：顶部只显示底层、底部只显示顶层、中段显示两层、无溢出不显示；滚动监听同时发布真实位置并同步视觉边缘。空值/非法色回退 `--pui-scroll-area-gradient-overlay-color-context`（默认当前主题容器色，页面壳可指定画布色），合法 `#hex`、`rgb()`、`rgba()` 或 `var(--token)` 同时驱动两层。`gradientOverlaySize` 只接受 `sm`、`md`、`lg`，两端对应 `40rpx / 20px`、`64rpx / 32px`、`88rpx / 44px`，非法值回退既有默认 `md`；它只改变两层高度，不能改变视口、Slot、滚动或定位。`height` 只接受正数、正 rpx 或正 px，`0`、负数、空值与非数字分别回退为原生 `320rpx`、H5 `160px`，不能坍缩成 1px。官网概览明确传入 `1128rpx`，H5 对应 `564px`，并以 H5 与当前 WXML 共用的 18 项真实 PUI Cell Slot 内容填满 shadow-safe 可用预览高度后形成真实滚动区；该演示值不改变公开默认 `320rpx`。组件没有横向滚动、阈值、禁用、实例方法或可配置动画 API。
22. Select 的小程序端由 PUI Button Trigger、PUI Popup 与 PUI Button 选项组成；H5 可见 Trigger 与 Option 同样调用共享 PUI Button 镜像，菜单使用主题 Surface，浏览器原生 select 只可作为不可见事件桥接。两端必须使用相同的严格原始值、受控 value、空 options、disabled/readonly 和禁用选项边界；选择只沿 `input/change` 的 Props 回写路径更新，不能保留独立的伪选中运行态。Option 的普通/选中背景共享 Trigger 的控制圆角（小程序 `--pui-radius-medium`，H5 `--pui-site-radius-control`）；H5 选中项必须恢复 PUI Button 的品牌文字与柔和背景，透明 Button 的零圆角/透明背景只能存在于未选中的基础态，不能覆盖选中 Surface。
22a. Combobox 的 Option 是组件自身的 listbox 交互根：普通行透明，只有已选行出现背景；该独立选择 Surface 必须在小程序显式使用 `--pui-radius-medium`、在 H5 使用 `--pui-site-radius-control`，并在果味/大圆角下同步变化。Sidebar 默认条目仍是连续导航轨道，不能把每行变成圆角卡片；仅 `theme=card` 的独立条目使用小程序 `--pui-radius-medium` 与 H5 `--pui-preview-radius-medium`。DropdownMenu、NavigationMenu 已经由共享 PUI Button 的控制/round 圆角承担；Tabs、Tabbar、Table、Cell、VirtualList 和 Picker 是连续轨道、行、指示器或滚轮焦点，不得机械套入该 Surface 规则。
23. Sheet 的 H5 镜像必须与原生共享受控/非受控 visible、header/default/footer slot、Button/Cell/Tag/Loading/Empty 组合、`error > loading > empty > content`、遮罩/关闭/retry、真实正文滚动、距离/速度下拉阈值和 after-* 来源。底层入口在隐藏、进入、显示和离开阶段都必须保留；打开时只把透明的完整 viewport layer 叠加到入口之上，禁止用独立 Host 底板或整段重绘清空预览上下文。默认 error/empty 必须调用共享 `emptySample`；与原生 WXML 一样，Error 的 PUI Empty 与 Retry Button 为兄弟节点，不能把动作私自塞进 Empty 或重画 Icon/标题。状态层和 Sheet 面板负责唯一 Surface，嵌入 Empty 不重复底色、边框、圆角、阴影或毛玻璃。受控操作只能请求 Props 回写，footer 与 retry 不得伪造业务成功；disabled 阻止用户关闭/拖拽但不阻断实例 `open()/close()`。H5 用 Pointer Events + 局部 overflow 近似小程序 touch + scroll-view，`minHeight/height/maxHeight/dragThreshold` 按 `1px≈2rpx` 映射；指针离开把手后仍须在 window 收尾，关闭保留节点到 0–1000ms 退场完成，reduceMotion 与 prefers-reduced-motion 均压缩为 1ms。375px 下正文、状态、footer 和把手必须保持完整内距且无可见溢出。
24. DateTimePicker 直接组合 PUI Picker，将年、月、日、时、分、秒动态列映射到同一 Popup、草稿和确认/取消合同。H5 必须复用 Picker 滚轮与共享 `iconButtonSample`，真实支持点击、键盘、wheel 与 Pointer 拖动，并同步 22 Props、`type=default|classic`、闰年/月末、范围、步长、周几、格式、时间戳 `0`、受控 value/visible、内联模式、disabled/readonly 与 500ms/1ms 动效。默认 Popup Header 必须是左 primary Check 圆形图标确认、标题居中、右 default Close 圆形图标取消；禁止恢复浏览器 date/time input 的分裂提交模型；可视月历和范围选择继续由 `Calendar + Popover` 组合承担。
25. Search 的 H5 镜像必须直接组合共享 PUI Input/Button/Icon，并区分受控 value 与非受控运行态；`0`、`false`、空字符串和 controlled → uncontrolled 必须保持严格。真实输入只发 change，清空固定 `clear → change`，确认、cancel、focus/blur、clearTrigger、shape/center、maxlength/maxcharacter、disabled/readonly 和 ariaLabel 均与 WXML 同源；固定 500ms/1ms 动效，不再公开私有 duration/easing。Search 原生组合必须监听 PUI Input 的 `change/enter`，禁止恢复不存在的 `input/confirm` 监听。round 通过 Input 公开的字段圆角语义变量消费 `--pui-radius-round`，普通形态消费 `--pui-radius-medium`；两者都保持 `bordered=true`，由 ConfigProvider 的中性边框 Token 控制可见性，不能在 Search 层私自关闭。官网按“基础用法 / 搜索框形状 / 操作与长度 / 状态与受控”分区，不得在镜像下方虚构组件目录结果、数据卡、Loading/Empty/Error 或不存在于 WXML 的业务列表，也不能以局部结果覆盖受控 value。
26. Stepper 的 H5 镜像必须通过共享 `inputControlSample` 与 `iconButtonSample` 组合 PUI Input/Button/Icon，映射受控/非受控值、`min/max/step` 规整、integer、inputWidth、size、theme、disabled、readonly、disableInput、ARIA 与固定 500ms/1ms 动效。直接输入只更新草稿，Enter 或失焦才提交一次 change；失焦顺序固定 `change → blur`，边界继续点击只发 overlimit，不伪造 change。受控请求必须由 Props 父级真实回写，`0` 合法，false/空字符串规整到下界，controlled → uncontrolled 延续最后渲染值。官网按“基础用法 / 主题与尺寸 / 步长与边界 / 状态与输入”分区；单位、Loading、Empty、Error 与 Retry 是消费方组合，不属于 Stepper Slot 或内部状态。
27. Slider 的 H5 镜像必须以真实 range input 映射微信原生横向单拇指 slider：浏览器 input 对齐连续 `changing`，浏览器 change 只提交一次 `change`；受控/非受控、退控保值、`min/max/step`、name、blockSize、disabled/readonly、showValue/showMinMax/valueSuffix、安全颜色与事件详情都须生效。拖动期间关闭轨道追赶动画，固定 500ms；`reduceMotion` 和 `prefers-reduced-motion` 压缩为 1ms。H5 方向键/Home/End 是增强，range/vertical/marks/capsule 不属于当前小程序合同；Slider 无 Slot 或实例方法。
28. DynamicMessage 的 H5 镜像必须与原生共享 `theme/title/message/icon/actionText/closable/duration/safeArea/shadow/frostedGlass/ariaLabel/reduceMotion`、`click/action/close`、`show/update/hide` 和零 Slots。`shadow/frostedGlass` 都是 `Boolean|null` 三态组件私有开关：`null` 继承全局 ConfigProvider，`true/false` 只强制当前通知开启或关闭，不能写入站点或小程序的全局视觉 Store。它是 PreviewDevice 内顶部 edge-to-edge 非模态浮层，不显示遮罩、不清空或锁定下方滚动内容；页面内容、Cell 与真实滚动在通知显示期间继续可用。Surface 固定使用中性反色黑底而不是 `primary`，浅色模式也保持独立高对比浮层；主题只改变状态 Icon 与一次性 edge-flow。流光与 Icon 共用同一语义色映射：loading 中性灰、info 信息蓝、success 成功绿、warning 警告橙、error 危险红，不得固定成绿色或整块染色 Surface。当前同 key 的 `show/update` 必须保留同一个 DOM 节点原位更新，主题默认 Icon 需随主题变化；不同 key 按调用顺序排队，移除未展示队列项不得伪造 close。进场固定为 `entering → compact(180ms) → expanding(320ms) → visible`：compact 只展示 PUI Icon/Loading 与标题，message、Action、Close 在 expanding 阶段随明确宽高边界淡入；进入 expanding 时必须用独立 transient class 启动一个 `aria-hidden`、不参与命中的 `1500ms` edge-flow。原生 `6rpx` / H5 `3px` 的装饰轨道只暴露顶部与右侧 L 形区域，内部只能有一束对角渐变光束连续移动；禁止让整段上边/右边依次换色冒充流动。面板在 `320ms` 后进入 visible 不得中断或重启流光；流光完成后只移除装饰 class，关闭或重开必须立即清理旧计时，不能改写根 Surface 的 background、backdrop-filter、box-shadow，也不能保留旧的满高竖向 accent、常驻彩边或循环动画。`1500ms` 是固定装饰例外，不是新的公共 Prop，也不能拖慢内容与操作的 `500ms` 可用时间。退场固定反向为 `collapsing(320ms) → leave-compact(180ms) → hidden`，收拢完成前不得卸载。loading 未显式指定 duration 时持续显示，其他主题默认停留 3000ms；自动、手动与命令式关闭必须在完整 500ms 退场结束后分别回传 timeout/manual/programmatic，低动效跳过可感知分段、压缩为 1ms 并完全取消 edge-flow。Indicator 必须调用 PUI Loading/Icon，Action 与 Close 必须调用 PUI Button/IconButton；动作只发布意图，不能自动宣称业务成功。标题、说明和操作在 390px 内保持可读与有界截断，安全区定位、light/dark、私有及全局外观开关、流光前中后 Surface 计算样式、队列中间态与无页面级横向溢出必须浏览器实测；微信胶囊坐标、fixed 合成、滤镜与流光叠层、字体回流、触摸命中、读屏和系统低动效保留真机风险。

## 最终预览站能力

`preview/index.html` 是当前组件库的 H5 交付预览入口。它需要覆盖完整组件规划清单，而不是只展示已完成组件。

当前标准组件页结构：

- 左侧：按“开始与规范、基础组件、布局、导航、表单组件、数据展示、反馈、浮层、高级”九组呈现中文组件名；表单组件内再按结构与校验、文本与搜索、选择与数值整理，日期、时间和附件选择入口统一进入选择与数值。PUI Input 提供原位过滤，`Ctrl/⌘ + K` 打开全局快速搜索 Dialog。
- 主区 Header：唯一页面标题，以及固定的 `概览 / API / 属性` PUI Tabs；机型和刷新/重置不进入 Header，而位于概览透明工具栏右侧。三个标签使用固定等分 Grid，选中块只以 transform 在三条固定轨道间移动，不动画 left/width、不测量 DOM；低动效为 1ms。页面 Tabs 不提供视觉 Hover，按钮始终保持透明；只保留主题感知的高对比选中 Surface 与独立 `focus-visible`。通用 Tabs 镜像中，`items≤4` 且 `spaceEvenly=true` 等分，`false` 使用 `80px` 横向最小轨道；`items>4` 固定使用 `22.222222%` 的 4.5 轨道，露出第五项的一半提示可横向浏览，与小程序同义。
- 概览：固定 `PreviewDevice`、常规/元素选择两种模式与真实组件交互；常规模式左侧以同一滚动正文显示同源的引用与基础代码块，元素选择按需显示上下文 Inspector。透明工具栏左侧承载模式切换，右侧整组承载机型、刷新、重置与复制。工具栏顶部固定消费 `--pui-preview-content-gap`（8px）内距，桌面/移动语义高度同步包含该值，不允许用外层空白节点补间距。
- API：独立 API Reference；五列参数表明确区分类型、演示初值与可选值。
- PROP：元信息、完整 Props 控件、WXML 引入和兼容说明，并只提供与概览共享的组件重置；不再存在常驻右侧 Inspector 或“预览/代码”私有切换。

当前交互要求：

- 所有组件清单项都必须可以点击，并展示对应预览。
- Props 面板调整后，预览和 WXML 示例必须同步更新。
- 所有可见固定字号不得低于 `12px`，固定像素行高不得低于 `16px`；微型 Badge 等也不能靠不可读文字换取紧凑。
- 官网所有 `font-family/font-size/line-height/font-weight` 声明必须消费 PUI Typography Token；Style Utilities、标准组件页和浮层不能各自维护字体数值。
- 属性、Props、状态区和弹层镜像必须保留明确 padding；H5 使用 `--pui-preview-panel-padding-*` 镜像小程序的面板语义 Token。常驻右侧 Inspector 已废弃，不得恢复第三列；元素选择模式的上下文 Inspector 只允许作为概览内按需浮层，不得复制完整属性。标准组件页的 Tabs 独占 Header 固定一级行；概览的模式、机型、刷新与重置进入内容区透明工具栏，模式切换在左，机型和动作整组居右。桌面 Header 使用标题说明与固定导航列顶对齐的 Grid。API/属性可以隐藏概览工具栏，Tabs 节点仍必须稳定复用；内容切换禁用页面滚动锚定副作用并恢复原视口锚点，不能因按钮数量、标题说明高度或内容高度移动 Tabs。
- H5 预览中的关闭、清空、翻页、步进、重试和播放/暂停等纯图标操作统一通过 `iconButtonSample` 组合 PUI Button 与 PUI Icon；不得用组件私有原生按钮复制同一能力。共享 Button 的 `default + base` 与小程序一致使用 `--pui-button-soft` / `--surface-soft` muted 弱填充、保留中性边界且无外投影；`iconOnly` 必须输出共享类，将 Button 与 PUI Icon 收敛在同一 `--pui-button-size` 的 Flex 居中轨道（`gap=0`），空内容节点不得参与布局。
- Sheet 默认关闭入口与 Popup 一致：使用 `default + base + circle + small + iconOnly` 的 PUI Button，并放在固定的 Header end 轨最右侧；H5 必须镜像该结构，不能以裸字符或 text 变体近似。
- Sheet 的拖拽柄是可见的独立交互提示：小程序使用 `--pui-text-placeholder`，H5 使用 `--subtle`；不能复用受全局无边框开关影响的 `--pui-border-color` / `--border`。
- Sheet 标题行的顶、左、右外侧 inset 必须与 Popup Header 同源：小程序使用 `--pui-surface-inset`，H5 使用 `--pui-preview-panel-padding`；拖拽柄以居中的绝对定位触摸区浮在顶边，不能再占用标题行文档流或缩小外侧对齐线。
- NavigationMenu 默认 Header 的 back/close 也属于此合同：必须调用 `iconButtonSample`，以 `outline + circle` 呈现 `28px` 的中性圆形按钮；不可用 back 仍保留禁用圆形轨道，不能退化为透明图标或裸关闭字符。
- H5 的复合 Button 内容统一通过 `buttonSample.defaultSlot` 组合；共享助手必须支持必要的 ARIA 角色与选择/展开状态。给原生 button 添加相似 class 不等于复用 PUI Button。
- 标准页基础设施也执行同一复用合同：左侧组件目录使用 Button + Badge，PROP 复制使用 Button + Icon，Icon 分类/卡片使用 Button + Icon，左侧搜索与机型选择使用 Input/Select helper；站点可通过受白名单保护的 `dataAttributes` 传递事件标识，但不得重新手写按钮或表单状态。原生 `input/select` 只能存在于对应 helper 的平台层。组件自身的触摸根、遮罩或底层平台节点不因此被机械包入 Button。Button 组合为资源卡等常驻 Surface 时，H5 必须用语义 Token 显式恢复底色、弱边框和 `data-shadow` 外观合同，不能被 Button `outline/text` 的透明底与无阴影规则覆盖。
- 共享 PUI Select 的 H5 可见层必须由 Button Trigger、Button Option、Chevron/Check Icon 与 Token Menu 组成；原生 select 只做 `pui-sr-only/aria-hidden` 值桥接，继续承载 `data-prop` 并派发真实 `input/change`。机型选择和所有枚举属性复用该实现，不能依赖浏览器/操作系统原生下拉的不可控配色。Enter/Space、ArrowUp/Down、Home/End、Esc、Tab、焦点恢复、禁用和外部关闭均属于合同。
- 深浅色验收必须在菜单或浮层真实展开后读取计算样式，而不是只检查 `data-theme`。Select、Picker 原生桥接、Menu、Dialog、Popover、Dropdown、Combobox、NavigationMenu、快速搜索和外观菜单的 Surface/文字/边界必须消费主题 Token；App Shell 与 input/select/textarea/option 必须继承对应 light/dark `color-scheme`，禁止硬编码浅色下拉层。
- 阴影等视觉偏好必须落到组件计算样式；预览 CSS 中每个无 fallback 的 `var(--*)` 都必须能在 CSS 根、组件运行时 style 或 `setProperty` 找到定义。普通独立 Surface 使用 `--shadow-soft`，浮层使用定义完整的 `--shadow`，毛玻璃使用 `--blur`；Cell、Field、Empty、Result、Grid、Steps 与 Avatar、Tag、Badge、Icon、Progress、Skeleton 的根不因 `data-shadow="on"` 获得外投影，保留的 selected/focus/divider inset 不视为阴影。等距模式同样只作用于独立 Surface，不改变连续集合条目和控件内部 gap。禁止通过新增同值私有别名掩盖未定义引用。全样式表必须通过自动 Token 引用扫描，开关关闭时再由统一选择器收敛为 `none`。
- 示例中的操作、图标、状态与输入应通过 `buttonSample`、`iconComponent`、`loadingComponent` 等 PUI 镜像助手生成，不重复写字符关闭图标、箭头或独立控件视觉。
- 原生 WXML 中组合 `pui-loading` 的组件必须进入 H5 Loading 覆盖清单；Icon/Loading 的尺寸通过 helper 参数按 `1px≈2rpx` 精确镜像，父级 CSS 只能负责 Slot 排列与颜色，禁止覆盖共享子组件的宽高、padding、圆角或使用 `!important`。不存在公开原生合同的私有 Choice 等镜像不得长期保留在预览代码中。
- 手机预览机必须是可操作实机，不允许只放静态假图；每个组件至少要有一个手机区域内的真实交互入口，例如点击、输入、切换、展开、打开/关闭、选择、上传模拟或刷新。
- 手机预览机统一使用固定 `622px` 高的 `PreviewDevice`，桌面宽度对应 375/393/430px，窄屏只收缩宽度。面板始终保留主题 Surface、边框、圆角和裁切；只有内部 viewport 使用 `overflow-y:auto`。滚动条空闲时透明隐藏，滚动期间显示；Dialog 不再使用透明 auto-height 外壳例外。
- 手机预览机的运行态和 Props 传参要分开：Props 面板体现组件 API，手机区域体现用户实际操作后的局部状态。
- 手机预览机的演示内容必须优先使用 PoemUI 内部组件语义组合，例如 `Icon`、`Button`、`Cell`、`Tag`、`Switch`、`Progress`、`Loading`；不要直接堆裸 SVG、裸按钮或一次性 HTML。
- 官网基础设施同样遵守组合合同：标准页 `概览 / API / 属性` 必须调用共享 `buttonSample`，刷新/重置/复制必须调用 `iconButtonSample`，搜索/机型必须调用 `inputControlSample` / `selectControlSample`；给手写原生控件借用 `pui-*` 类名不算调用组件。同步可访问名称或状态时只更新属性/Slot，不得清空共享组合树。Header 只保留固定 Tabs 行；概览使用透明工具栏，模式切换在左，机型、刷新、重置和复制整组居右对齐，复制当前组件效果代码固定在最右。工具栏不得建立 Surface，390px 换行后右侧工具组仍须右对齐，禁止通过 `window.scrollBy` 补偿布局位移。复制与属性页共用 WXML 生成器，只输出非默认 Props；注释记录视觉环境，H5 临时运行态不被序列化为小程序参数。
- 官网全局快速搜索属于站点导航增强：`Ctrl/⌘ + K` 打开固定边界 Dialog，输入、结果与关闭必须调用 PUI Input/Button/IconButton；结果按左侧九组分类并支持中文/英文/分类、ArrowUp/ArrowDown、Enter、Esc、Tab 焦点圈和遮罩关闭。该能力不得写入小程序组件合同或宣称微信端监听系统快捷键。
- Icon 资源页搜索同样调用 `inputControlSample(prefixIcon='search')`，不能以 `.icon-search` 重新实现 Input/Icon。查询更新会重建资源列表时，H5 必须恢复搜索焦点和光标；40px 工具栏高度使用 `--pui-site-icon-search-height`，其余 padding、字号、圆角、阴影与毛玻璃继续由 PUI Token 决定。
- PROP 配置不得成为复用合同的例外：`renderPropsPanel` 只组合 Input/Select/Switch/Slider/Textarea helper，原生表单节点仅保留在 helper 平台层。H5 输入事件必须真实写回 Props/WXML，重绘后恢复当前字段焦点；JSON 和 nullable number 解析失败时保持上次有效值并标记 `aria-invalid`，禁止假成功或静默吞错。
- 演示区、列表项、按钮组、宫格和浮层内容的间距必须走 H5 预览 spacing 变量，对应小程序 `xxs/xs/sm/normal/lg/xl/xxl/3xl` 规则；不要用负 margin 压缩列表项。
- 浮层、反馈、导航、表单、列表、选择器和上传类组件必须优先补齐可见状态变化，点击后要能在预览机中看到结果。
- 深浅色和 5 个视觉主开关是全局状态，不能互相覆盖状态。
- 5 个视觉主开关分别是：边框、阴影、毛玻璃、大圆角、渐变背景。
- ConfigProvider 的 H5 页面必须镜像真实 `theme/shadow/frostedGlass/largeRadius/bordered/equalSpacing/useGlobalConfig` Props，并展示安装端的真实入口：`visualConfig.restore/set/applyPreset/setEffectsEnabled/reset/subscribe`、每页根 `<pui-config-provider use-global-config>`、存储失败返回值和 App/Page 生命周期边界。H5 局部 Provider 只能镜像 Token 变化，不得伪装浏览器存储等价于微信 `wx.*StorageSync`。
- ScrollArea 默认渐变色必须在当前组件树解析 `--pui-scroll-area-gradient-overlay-color-context`：普通实底读取当前主题的 `--surface-solid`，`data-frost=on`、局部 frosted ConfigProvider 与 Popup card 则重绑定为 `--pui-scroll-area-gradient-overlay-material-color`（light/dark 分别为同色相 `.32` alpha），避免半透明 Surface 上出现纯白/纯深色带。H5 不能把浅色计算结果缓存到深色子树，也不能让 ScrollArea 根私自覆盖父级材质上下文；切换 dark/frost 后必须滚动到遮罩可见并读取实际渐变起始色，而不是只检查 `data-theme/data-frost`。显式 `gradientOverlayColor` 仍优先。
- 全局渐变开关只控制消费者页面背景，不能成为 ConfigProvider Prop、visualConfig 预设或组件 Surface；`effectsEnabled` 只总控 shadow/frostedGlass/largeRadius，不得覆盖 theme/bordered/equalSpacing。独立的 `pui-bg-gradient-*` utility 可由调用者直接挂在业务 View 或容器。
- Icon 页面必须支持分类筛选、搜索和点击选择图标；选择结果必须同步写入 `name` Props、实时预览与 WXML 示例代码。
- Icon 的跨端设计真相源是 `assets/icons-src`，运行时真相源则是生成的同一份本地 WOFF2、稳定码点和字体目录：小程序与 H5 都以字体字形和 `currentColor` 渲染。两端禁止 inline SVG、SVG path map、CSS mask/image 与 Canvas 图标分支；业务图片统一使用 `pui-image`。
- Accordion / Collapse 的手机镜像必须按“基础用法 / 多开与互斥 / 卡片与 Generic / 加载、空与错误”分区，支持受控/非受控、严格原始值、单开、多开、禁用、loading、error、retry 和 empty。面板点按只局部更新常驻内容节点；主题、Generic 和状态演示可重建对应 Showcase，但不能用整页重绘掩盖开合动画。基础 WXML 零 `bind:*`，完整 change/retry 只进入 API 或专项示例。
- Dialog 的手机镜像必须支持受控 Props 回写、内建/数组/具名 slot 动作、确认、取消、右上关闭、遮罩、180ms/1ms 进退场与 `close()`；Cancel 固定为 cancel→close，Confirm/Action 不自动关闭。Dialog 没有非受控内部值、默认 Slot、loading/error/empty/retry 或 after-close 合同；内容状态由 content Slot 的真实 PUI 组合承载。原生经 Popup 默认内容轨承载 Dialog 组合内容，并只通过 `visible-change` 获取遮罩关闭请求；遮罩同时遵守 prevent-scroll-through 与 overlayProps.backgroundColor。
- Alert 的手机镜像必须支持受控开关、关闭、主题、图标和 slot 组合；不得以整页重绘或即时隐藏代替退场。
- H5 页面允许展示 planned/research 组件的视觉草案，但必须在状态中标明它们还不是已发布小程序组件。
- 小程序反馈分区迁移不复制 H5 预览 DOM：Alert、Empty、Loading、NoticeBar、Progress、Result、Skeleton、Toast 的 H5 镜像继续以 `preview/app.js`、`preview/styles.css` 和各自组件合同为真相源；小程序独立页只组合同名 npm 组件、共享 Navbar/ScrollArea 与 `visualConfig`。两端都必须保留 Alert 受控回写、Empty action 父级边界、Loading/Skeleton 非业务状态、NoticeBar operation 父级回写、Progress 确定值、Result 页面操作与 Toast `show(options)/close` 的同一语义，不能把一端的调试信息、属性面板或私有状态搬到另一端。

## 新组件接入预览的步骤

1. 在 `docs/COMPONENT_MATRIX.md` 更新组件状态。
2. 创建小程序组件四件套。
3. 在 `preview/app.js` 增加组件元数据。
4. 在 `preview/app.js` 增加 Props 定义、预览渲染和 WXML 示例字段。
5. 在 `preview/app.js` 为手机预览机增加 `data-demo-action` 或 `data-demo-prop` 交互入口，并接入运行态更新。
6. 优先复用 `preview/app.js` 中的内部组件 helper 组合演示内容；新增 helper 时要保持 `pui-*` 语义类名。
7. 在 `preview/styles.css` 增加 H5 镜像样式和点击/选中/打开/关闭等状态样式，间距优先使用预览 spacing 变量。
8. 如果组件依赖生成数据，先补生成脚本和 `scripts/check-package.js` 门禁。
9. 跑 `npm run check`，再打开 `preview/index.html` 做桌面和 390px 移动端实机点击检查。

## ScrollArea 尾部安全区补充

ScrollArea 的透明内容轨公开 `contentPaddingBottom`：默认 `10vh`，接受非负裸数、`rpx`、`px` 或 `vh`，`0` 可关闭，非法值回退 `10vh`。小程序与 H5 都把它计入真实 `scrollHeight`，保证最后一项可滚到遮罩和屏幕底部之上；绝对定位浮层的消费者可在展开期间提高该值，关闭后恢复默认。该 API 不扩张为四向 padding，也不改变根、视口、遮罩、定位或 Slot 的 Surface 语义。

## Popup Surface 顶边反馈补充

Popup 的 `surface-top` Slot 必须作为 Surface 内第一个节点并先于 Header，专门承接不占布局高度的顶部反馈。小程序与 H5 都由 Popup Surface 提供相对定位和圆角裁切；H5 使用共享 `topLoadingPreviewMarkup` 镜像消费者 TopLoading。禁止把顶部轨道放进 Content，或以页面私有绝对定位补偿到面板顶边。

## AreaChart / BarChart / Waffle 数据图形补充

三类图表的 H5 概览必须由 `preview/app.js` 根据同源结构化数据生成真实图形，并与小程序共享非负值规整、主题白名单、共享零基线和可访问摘要语义。AreaChart 使用真实 SVG path/linearGradient/grid/x-axis/legend，镜像小程序 Canvas 2D 的 `AreaChartItem[]`、natural/linear/step 和 stacked；禁止 Canvas 截图或固定 SVG。BarChart/Waffle 使用真实 DOM。BarChart 横向/纵向分别消费同义的 90deg/0deg 渐变 Token，固定为 AreaChart 式 `0.04 → 0.42` 透明填充，并用实体 accent inset 线标注数据端；Waffle 单元消费 `--pui-chart-cell-gradient-*` 并保留目标 opacity 与 inset outline；AreaChart 使用实体强调色描边与 `--pui-chart-area-fill-start/end` 竖向渐变。三者进入标准 `PreviewDevice shadow-safe`，根保持透明且不消费 Surface 阴影、毛玻璃、边框或等距。0.1.2 小程序 Battle 已改 `common/style/theme.wxss` 与 `bar-chart/bar-chart.wxss`；最终 H5 批次必须同步 `preview/styles.css` 的浅深六色横纵 Token、segment 终点线与专项测试，`preview/app.js` 保持现有主题映射，完成前状态为待同步。

三类图表统一镜像 `animated=true / duration=500 / replay()`：渲染后下一帧进入，重播 IconButton 只重置入场 class，不重建数据或伪造成功。`animated=false` 首帧即完成，`reduceMotion=true` 为 1ms 且无延迟。H5 必须在 390px、light/dark、shadow/frost/border/large-radius/equal-spacing 组合下验证无横向溢出、真实渐变/描边可见、重播有效且根计算样式不获得 Surface 效果。

小程序 Me 页把公告 Schema v2 的最早/最新 `categoryCounts` 转换为九类 `baseline/increment` 水平堆叠 BarChart，这属于应用消费逻辑，不复制成官网业务页；当前基线为 `v0.1.0`，当前版本为 `v0.1.2`，只有高级类为 `5+3`。H5 仍必须维护 BarChart 的结构化 items、共享零基线、horizontal/stacked、Grid、Value、Legend、动效与透明 Surface 公共合同；不得为了展示 Me 再维护一份静态浏览器统计，也不得把 BarChart 组件 H5 验证写成 Me 小程序页面已经验收。

## 禁止事项

- 不要在 H5 中写 `wx:if`、`wx:for`、`bindtap`。
- 不要在 H5 CSS 中使用 `rpx`。
- 不要为了 H5 展示修改组件 `.wxml/.wxss` 的真实结构。
- 不要把浏览器专用 DOM API 写进小程序组件源码。
- 不要假设 H5 的毛玻璃模糊效果在所有微信基础库里完全一致。
- 不要把毛玻璃、阴影和大圆角写成同一个开关；它们必须能独立控制。

## 0.1.4 新增镜像与主题继承补充

- ActionSheet、PullRefresh、DropdownMenu 的小程序根在空 `colorScheme` 时继承最近 Provider；H5 不需要复制微信 Theme Behavior，但展开层和真实 Surface 必须读取当前 App Shell 主题 Token，不能固定浅色。
- PullRefresh 的 H5 根与内容轨是透明滚动基础设施：固定 `background:transparent / border:0 / box-shadow:none / backdrop-filter:none`。全局外观不能把它变成 Surface。
- DonutChart 以结构化 SVG 镜像小程序 Canvas 2D 圆环，RadarChart 以 SVG 镜像网格、轴线、数据面积、节点和标签；两者都必须保留数据切换、ARIA、replay、500ms/1ms 和透明展示叶子资格。
- SortableList 的 H5 镜像必须保留一个集合 Surface 和一个滚动上下文，支持 Pointer 拖动、边缘自动滚动、键盘 Arrow 排序、受控回写和焦点恢复；不能以每行 Card 或第二根滚动容器代替。0.1.4 只承诺活动行状态过渡，Pointer/键盘顺序回写不得被描述为兄弟行让位或落位动画；PUI-FB-0530 已按用户决定关闭。
- Tour 的 H5 镜像使用四块 Mask 让目标区域保持真实可见，Panel 必须受 PreviewDevice 边界约束；Esc、焦点圈、关闭后恢复触发者、目标缺失失败关闭和外观资格都要实测。
- 浮层阴影变量必须在当前 `data-shadow` 状态下重新绑定，不能在根级先把 `--shadow-floating` 解析成 `none` 后永久缓存。验收必须读取 Panel 的实际 `box-shadow`，不能只检查根数据属性。
- 逐组件运行态与 390px 证据记录在 `docs/RELEASE_0.1.4_H5_CHANGELOG.md`；H5 通过不等于微信开发者工具或 iOS/Android 真机通过。
