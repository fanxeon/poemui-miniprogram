# PoemUI 组件语义合同模板

本模板用于为真实组件建立长期语义合同。创建合同前必须完成源码、预览、API、示例、测试和 Feedback Ledger 审计；不得只替换组件名后提交空壳。

文件名使用组件 ID 的全大写形式，例如 `input` 对应 `INPUT.md`。不适用的章节需要说明原因，不能静默删除关键边界。

```markdown
# <ComponentName> 组件语义合同

本文是 PoemUI <ComponentName> 的长期设计与实现合同。任何 Agent 修改源码、H5 镜像、示例、元数据或相关 Token 前，都必须完整阅读本文，并查询：

`npm run feedback:list -- --component <component-id>`

Props、事件和方法的完整清单以 `docs/COMPONENT_API.md` 为准；本文不复制完整 API 表。

## 1. 组件定位

- 组件解决的用户问题。
- 适用和不适用场景。
- 与相邻组件的职责边界。

## 2. 固定结构与区域

- 用结构树说明稳定的语义区域。
- 哪些区域条件渲染，哪些始终存在。
- 每层容器真实的布局、分组或交互职责。

## 3. PUI 组合与依赖

- 必须复用的 PUI 子组件。
- 允许使用平台原生根节点的底层边界。
- 禁止重复手写的能力。

## 4. Token、间距与排版

- 使用的语义 Token、默认值和 H5 镜像值。
- 区域间距、内容间距和控件内距的关系。
- 字号、行高、圆角、边框、阴影和颜色边界。

## 5. 内容、Slot 与组合边界

- Slot 名称、启用条件和责任。
- 父组件允许管理的布局范围。
- 父组件不得穿透覆盖的子组件几何。

## 6. 状态与优先级

- content/loading/error/empty/disabled 等状态优先级。
- 状态切换时必须保持稳定的结构和尺寸。
- 失败、取消、重试和恢复路径。

## 7. 交互、受控边界与事件

- 受控/非受控判定和回写规则。
- 用户动作、方法、事件顺序和 source。
- loading、禁用、防重复提交和回撤边界。

## 8. 可访问性

- 语义角色、可访问名称和键盘行为。
- 焦点、错误、选中、低动效和 text-cut 边界。

## 9. H5 预览与跨端一致性

- H5 如何镜像真实 WXML/WXSS 能力。
- 标准 PreviewDevice 中的入口、结果和浮层边界。
- 必须明确组件预览采用 `shadow-safe` 还是 `edge-to-edge` 父布局，并说明它与真实使用场景的关系；禁止通过页面私有 margin 修复阴影裁切。
- 平台差异必须明确说明，禁止伪造能力。

## 10. 响应式、主题与视觉配置

- 390px、light/dark、边框、阴影、毛玻璃、大圆角和渐变要求。
- 全局 ConfigProvider 对组件的作用边界。

## 11. 明确禁止

- 列出最容易被 Agent 误实现、且必须长期阻止的结构和行为。

## 12. 修改闭环

1. 列出必须同步审计的源码、预览、文档、元数据和示例。
2. 列出专项测试、构建、390px/主题/外观验证。
3. 记录需要更新的 Feedback Ledger 和真实设备风险。

任何不能满足本文的实现必须在 Ledger 中说明原因，不得静默绕过。
```
